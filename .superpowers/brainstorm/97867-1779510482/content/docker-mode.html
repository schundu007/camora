What does "Docker" mean in the playground?

Docker has a few distinct use-cases — pick the one that matches your practice goal

A

Write & build a Dockerfile

You type a Dockerfile in the left pane. Hit Run → the right pane shows the live docker build output (layer-by-layer). Good for practicing image creation.

Pro

  • Real image build feedback
  • Closest to real workflow

Con

  • Slow (pulls base images)
  • Fills disk over time
B

Validate / lint only (no build)

You type a Dockerfile. Hit Run → the right pane shows hadolint or dockerfile-lint output — syntax errors, best-practice warnings. Fast, no Docker daemon needed.

Pro

  • Instant feedback, safe
  • No image bloat

Con

  • Doesn't catch runtime issues
C

Run docker CLI commands

Left pane is a shell script of docker commands (docker run, docker ps, docker exec…). Hit Run → output on the right. Like a Docker-flavoured Bash scratch pad.

Pro

  • Flexible, practice any docker command

Con

  • Full daemon access = security risk on server

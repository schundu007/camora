# Publishing playbook — Camora mobile

This file is the single source of truth for shipping `apps/mobile` to the App Store and Play Store. Treat it as a runbook, not a tutorial — every step says **who does it** and **how long it takes**.

## Phase 0 — accounts (you, ~3 days elapsed)

| Step | Who | Cost | Wait |
|------|-----|------|------|
| Create Apple ID for Cariara LLC (or use personal) | you | free | minutes |
| Enroll in Apple Developer Program | you | $99/yr | 24–48 hrs verification |
| Get a D-U-N-S number if registering as an org | you | free via Apple | up to a week — start now if needed |
| Create Google Play Console account | you | $25 once | hours |
| Verify identity on Play Console | you | free | hours |
| Pay tax + banking forms in App Store Connect | you | — | 30 min, done in browser |
| Same in Play Console | you | — | 30 min |

While Apple verifies, the rest of this playbook can run in parallel.

## Phase 1 — local tooling (Claude or you, ~30 min)

Run from `apps/mobile/`:
```bash
pnpm install                               # if not already done
npm i -g eas-cli                           # global, used by EAS Build
eas login                                  # browser-based, opens your Expo account
eas init --id <auto-generated-or-pasted>   # links the local repo to an EAS project
```

`eas.json` is already committed. After `eas init`, Expo writes the `extra.eas.projectId` field into `app.json` automatically — commit that change.

## Phase 2 — App Store Connect setup (you, ~2 hours)

1. App Store Connect → My Apps → "+" → New App
2. Bundle ID: `com.cariara.camora` (must match `app.json`)
3. SKU: `camora-mobile-001` (any unique string, internal only)
4. Primary language: English (US)
5. Fill the listing from `store/app-store.md` — title, subtitle, description, keywords, URLs, category
6. Upload icon (1024 × 1024 from `assets/icon.png` — replace with real artwork before this step)
7. Upload screenshots from `store/screenshots-checklist.md`
8. Fill **App Privacy** section using `store/privacy-answers.md` (Apple side)
9. Fill **App Review Information** — sign-in credentials, contact email/phone, notes for reviewer
10. Note the **App Store Connect App ID** (numeric, top of the App Information page) → paste into `eas.json` `submit.production.ios.ascAppId`
11. Note your **Apple Team ID** (account.apple.com → membership) → paste into `eas.json` `submit.production.ios.appleTeamId`
12. Commit the `eas.json` change

## Phase 3 — Play Console setup (you, ~2 hours)

1. Play Console → Create app → name "Camora — Interview Prep & Audio"
2. Default language: English (US), free app
3. Declarations: not directed at children, complies with Play policies, US export laws
4. Fill the listing from `store/play-store.md`
5. Content rating → complete IARC questionnaire using answers in `store/play-store.md`
6. Data safety → fill from `store/privacy-answers.md` (Play side)
7. Upload feature graphic (1024 × 500) — **Play rejects without it**
8. App access → provide test credentials so Play reviewers can log in
9. **Service account for `eas submit`**:
   - Google Cloud Console → IAM → Service Accounts → create one named `play-publisher`
   - Grant role "Service Account User"
   - Create a JSON key, download it
   - Save as `apps/mobile/store/play-service-account.json` (already in `.gitignore`)
   - Play Console → Setup → API access → Link → invite the service account, grant "Release manager" permission

## Phase 4 — first build (Claude, runs unattended ~20 min)

```bash
cd apps/mobile

# Internal preview — install on your phone via QR code, no review needed
eas build --platform all --profile preview

# After the preview is approved by you, real production builds:
eas build --platform all --profile production
```

EAS will:
- generate a new iOS distribution certificate + provisioning profile (or use existing — it asks)
- generate or reuse the Android upload keystore
- run the build on Expo's macOS / Linux servers
- post the artifact URL when done (~15 min iOS, ~10 min Android)

The first iOS build always asks for App Store Connect credentials — sign in via the browser when prompted.

## Phase 5 — submit to TestFlight + Play Internal (Claude, ~10 min + reviewer wait)

```bash
cd apps/mobile
eas submit --platform ios --latest      # uploads the .ipa to TestFlight
eas submit --platform android --latest  # uploads the .aab to Play Internal
```

- iOS: TestFlight processing takes 5–30 min, then you can install on your iPhone via the TestFlight app.
- Android: appears in Play Internal Testing within minutes — install via the opt-in link Play gives you.

Test on a real device. Walk the full happy path: login → prep → audio interview consent → record → transcript → Sona answer.

## Phase 6 — submit to App Store + Play Production review (you, ~1 week elapsed)

When the TestFlight build is solid:

**iOS**:
1. App Store Connect → your app → TestFlight → "Submit to App Store" on the build
2. Confirm metadata, screenshots, privacy, sign-in info
3. Submit for review
4. Apple review window in 2026: typically 24–48 hrs. Plan for one rejection round.

**Android**:
1. Play Console → Production → Create new release
2. Promote the Internal build OR upload a fresh `eas build --profile production` artifact
3. Release notes (use the latest commit summary)
4. Roll out at 20% initially, monitor for crashes for 24 hrs, then ramp to 100%

## Likely Apple rejection causes — current mitigation status

| Risk | Guideline | Mitigation in code |
|------|-----------|--------------------|
| Reader-app rule | 3.1.3 | iOS Account screen no longer deep-links to web checkout (`AccountScreen.tsx` Platform.OS check). |
| Academic dishonesty | 5.6.1 | All copy reframed: "transcribes + surfaces context from your prep", never "Sona answers". Reviewer notes (in `store/app-store.md`) state explicitly "for job interviews, not academic exams". |
| Minimum functionality | 4.2 | Prep tab is wired to real, navigable bundled topic content (`src/data/topics.ts` — 4 categories × 6 topics with full bodies). No "Coming soon" placeholders remain. |
| Account deletion missing | 5.1.1(v) | Account screen → "Delete account" → confirmation → DELETE /api/auth/account. Backend endpoint already exists. |
| Privacy nutrition label mismatch | 5.1.2 | `store/privacy-answers.md` is the source of truth. Update it AND App Store Connect on the same day if a tracking SDK is ever added. |
| Recording without visible indicator | 5.1.1(ix) | Red sticky banner shows "Recording — M:SS" during active record + auto-stop in countdown. iOS system orange dot also appears. |
| Background recording surprise | 5.1.1(ix) | Hard 10-minute cap (`MAX_RECORDING_MS` in `AudioInterviewScreen.tsx`). No auto-loop, no continuous mode. Mic releases on stop and on screen unmount. |

## Likely Play Store rejection causes — current mitigation status

| Risk | Policy | Mitigation in code |
|------|--------|--------------------|
| Sensitive permissions without disclosure | Permissions & APIs | Mic permission string explains exactly what it's for. Foreground-service mic declared in app.json. `blockedPermissions` removes location/contacts/camera so they can't be auto-merged from native libraries. |
| Data Safety form mismatch | Data Safety | `store/privacy-answers.md` is the source of truth. Audio is "Collected, not shared." |
| Account deletion missing | User Data — Account Deletion | In-app delete flow same as iOS; web alternative documented in support page. |

## After v1 is live

- Universal Links / App Links so the auth handoff (`/mobile/auth`) opens the app directly without the `camora://` custom-scheme hop. Needs `apple-app-site-association` + `assetlinks.json` served by `camora.cariara.com`.
- Real artwork (icon, splash, feature graphic) — the placeholder PNGs in `assets/` are intentionally bland.
- Per-token streaming on the Audio Interview screen via `react-native-sse` so Sona's answer types out instead of arriving in one chunk.
- iOS App Tracking Transparency prompt — only required if a third-party tracking SDK is added; not needed for v1.
